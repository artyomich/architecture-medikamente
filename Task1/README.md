# Задание 1. Анализ безопасности системы

## 1. Выявленные конфиденциальные данные

Следующие категории данных обрабатываются в текущей архитектуре, но **не имеют должной защиты**:

| Категория данных                              | Тип (по ФЗ-152)                   | Уровень конфиденциальности | Учтены в системах? |
|----------------------------------------------|----------------------------------|----------------------------|--------------------|
| ФИО, дата рождения, телефон, email           | Персональные данные (ПДн)       | Конфиденциальные           | ✗ частично         |
| Адрес прописки, место работы/учёбы           | ПДн (расширенные)               | Конфиденциальные           | ✗ нет              |
| Хронические заболевания, история болезни     | Медицинская тайна (ФЗ-323)      | Секретные                  | ✗ нет              |
| Результаты анализов, заключения              | Медицинская тайна               | Секретные                  | ✗ частично         |
| Договоры, данные об оплате                   | Финансовые + ПДн                | Конфиденциальные           | ✓ только в 1С      |
| Журналы приёма (Excel, PDF)                 | Метаинформация + ПДн            | Конфиденциальные           | ✗ нет              |

> 💡 **Вывод**: Большинство чувствительных данных хранятся **вне систем с контролем доступа**, на общем файловом сервере, без шифрования и аудита.

## 2. Проблемные зоны и несоответствия

| № | Проблема                                                                                          | Несоответствие требованиям                                                                                   |
|---|---------------------------------------------------------------------------------------------------|--------------------------------------------------------------------------------------------------------------|
| 1 | Отсутствие классификации и тегирования данных                                                     | Нарушение требования «разграничения по уровням доступа» (п. 19 ФЗ-152)                                       |
| 2 | Хранение ПДн и медицинской тайны в Excel/PDF на общем диске                                       | Отсутствие защиты при хранении (п. 19 ФЗ-152, ст. 22 ФЗ-323)                                                |
| 3 | Доменная аутентификация без RBAC/ABAC                                                             | Нет разграничения доступа по ролям → нарушение Принципа наименьших привилегий                                |
| 4 | Отсутствие аудита операций с данными                                                              | Нет возможности выявить утечку → нарушение п. 19(4) ФЗ-152                                                  |
| 5 | Файловый режим 1С                                                                                 | Не поддерживает RBAC/аудит на уровне записей → риск доступа к чужим данным                                   |
| 6 | Ручные передачи данных между системами (Excel → 1С → файловый сервер)                             | Нет контроля целостности и происхождения данных → нарушение Data Lineage                                     |
| 7 | Отсутствие шифрования при хранении и передаче                                                    | Нарушение требований к защите (п. 19 ФЗ-152)                                                                |
| 8 | Нет инструментов DLP, SIEM, мониторинга нетипичных действий                                       | Невозможно обнаружить утечку вовремя                                                                        |
| 9 | Отсутствие управления согласиями и DSAR-процессов (запросы на удаление/предоставление данных)      | Нарушение права субъекта ПДн (ст. 14, 18 ФЗ-152)                                                             |
|10 | Нет гарантии хранения данных **только на территории РФ**                                          | Потенциальное нарушение требований Роскомнадзора                                                             |

## 3. Система тегирования данных

### **Теги безопасности**

| Категория     | Значения                                     | Описание                                                                 |
|---------------|----------------------------------------------|--------------------------------------------------------------------------|
| **Уровень**   | `PUBLIC`, `INTERNAL`, `CONFIDENTIAL`, `PII`, `PHI`, `FINANCIAL` | Уровень конфиденциальности                                               |
| **Домен**     | `OPERATIONAL`, `ANALYTICAL_BI`, `ARCHIVE`    | Контекст использования                                                   |
| **Цель**      | `CONSENT`, `DSAR`, `AUDIT`                   | Используется для управления согласиями и запросами                       |

> Инструмент управления метаданными и тегами: **Apache Atlas** (интегрируется с Kafka, NiFi, Spark, Kubernetes).

## 4. Список данных для защиты и меры защиты

| Данные                                    | Теги                                         | Хранение      | Передача       | Использование                        | Аналитика (BI/ML)                   |
|------------------------------------------|----------------------------------------------|---------------|----------------|--------------------------------------|--------------------------------------|
| ФИО, email, телефон                      | `PII`, `OPERATIONAL`                         | AES-256       | TLS 1.3        | Динамическое маскирование            | Статическая маскировка               |
| Дата рождения                            | `PII`, `OPERATIONAL`, `ANALYTICAL_BI`        | AES-256       | TLS 1.3        | Полный доступ (роли: врач, ресепшн) | Без изменений                        |
| Адрес, место работы                      | `PII`, `OPERATIONAL`                         | AES-256       | TLS 1.3        | Только для врачей/ресепшена          | Гео-обфускация                       |
| Диагнозы, история болезни                | `PHI`, `OPERATIONAL`                         | AES-256       | TLS 1.3        | Только для лечащего врача            | Полное обезличивание                 |
| Результаты анализов                      | `PHI`, `OPERATIONAL`, `ANALYTICAL_BI`        | AES-256       | TLS 1.3        | Врач + лаборатория                   | Обезличенные агрегаты                |
| Договоры, платежи                        | `CONFIDENTIAL`, `FINANCIAL`, `OPERATIONAL`   | AES-256       | TLS 1.3        | Кассир, бухгалтер                    | Без идентификаторов                  |
| Журналы приёма                           | `PII`, `OPERATIONAL`                         | AES-256       | TLS 1.3        | Врач, ресепшн                        | Агрегированные данные (без ФИО)      |

> **Обфускация** применяется при передаче в аналитические системы и API-интеграциях.  
> **Шифрование** — на всех этапах жизненного цикла (at rest, in transit, in use — через TEE или application-level).

## 5. Механизмы и инструменты защиты

| Угроза / Требование                     | Инструмент / Решение                                                                 |
|----------------------------------------|--------------------------------------------------------------------------------------|
| Аутентификация                         | 2FA + LDAP/Active Directory + OAuth2 / OpenID Connect                                |
| Авторизация                            | RBAC + ABAC на базе Keycloak или Auth0 + тегов из Apache Atlas                       |
| Шифрование данных                      | AES-256 (at rest), TLS 1.3 (in transit), HashiCorp Vault (управление ключами)        |
| Обфускация / Маскирование              | Apache ShardingSphere, Dynamic Data Masking в Postgres                               |
| Аудит и логирование                    | Apache NiFi → Kafka → ELK + Prometheus/Grafana + SIEM (Wazuh)                        |
| Защита от утечек (DLP)                 | OpenDLP или коммерческий DLP + правила на основе тегов Atlas                         |
| Управление согласиями и DSAR           | DataGrail или кастомный сервис на базе Kafka + Atlas                                 |
| Целостность данных                     | Контрольные суммы, цифровые подписи, блокчейн-журналы (опционально)                  |
| Резервное копирование и восстановление| Velero (K8s) + MinIO (S3-compatible) + регулярные DR-тесты                           |
| Хранение в РФ                          | Размещение всего стека в дата-центре РФ (Yandex.Cloud, VK Cloud, Selectel)           |
| Data Lineage                           | Apache Atlas + Kafka Streams + OpenMetadata                                          |
